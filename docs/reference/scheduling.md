# 排程規則

任務排程（工期、相依、實際進度、工作日曆）與計畫的規則。這份是唯一出處：程式註解寫「規則見 docs/reference/scheduling.md〈小節〉」，指的就是這裡的小節標題。

- 改規則時先改這份，再改程式與測試。〈檢查點（測試向量）〉的數字由 `frontend/src/__tests__/readme.spec.ts` 對照程式推算，沒跟上會紅。
- 後端目前不跑排程：前端算好寫回（見〈存與算的分工〉）。之後做任務 API、或要在後端算專案摘要時，照這份移植同一套排程，並跑〈檢查點（測試向量）〉。

## 名詞

| 名詞           | 意思                                                                      |
| -------------- | ------------------------------------------------------------------------- |
| 工作天         | 要上班的日子，由工作日曆決定（見〈工作天〉）                              |
| 工期           | 任務要花幾個工作天；使用者輸入的值（`Task.duration`）                     |
| 前置／後續任務 | 相依 `from → to`：`from` 是前置，要先完成；`to` 是後續任務                |
| 根任務         | 沒有前置的任務                                                            |
| 已開始         | 狀態是進行中、暫停或完成                                                  |
| 推算起訖       | 照本文件的規則，用今天與工作日曆算出的開始日、結束日。畫面一律顯示它      |
| 存的值         | 資料裡的 `start`／`end`：輸入值或上次寫回的推算結果（見〈存與算的分工〉） |
| 逾期           | 進行中或暫停，照工期該結束的日子早於今天                                  |
| 計畫           | 只用 PM 輸入的東西排出來的起訖，存在基準欄位（見〈計畫與延遲〉）          |

## 工作天

工作日曆來自 `GET /api/calendar`（`WorkCalendar`），全系統共用。

1. `days` 裡有那天：照它的 `isWorkday`。放假日是 false，補班日是 true。
2. 沒有：ISO 星期（1＝週一…7＝週日）在 `weekendDays` 裡就放假，其他上班。

- 不在 `coveredYears` 的年份，`days` 沒有資料，只看週末。畫面提示「YYYY 年假日未公布，只排除週末」。
- 日曆還沒載入或載入失敗：只看週六日。載入失敗時畫面提示「假日資料載入失敗，只排除週末；重新整理可重試」。
- `name` 只供顯示（假日名稱），不拿來判斷。

## 工期

- 整數，1–3650 個工作天。0、負數、非數字當 1；小數四捨五入；超過 3650 當 3650。
- 起訖都算：`[開始日, 結束日]` 之間的工作天數＝工期。結束日一定是工作天。
- 開始日本身不是工作天時（例如實際開工在週六），從下一個工作天算第 1 天。
- 只有任務的工期是工作天。專案總時長、分類期間是日曆天（含週末與假日），畫面的 title 寫明單位。

## 開始日

依相依的先後算，前置先算。相依保證沒有環（建立相依時用 `reachable` 擋）；萬一資料有環，環上那條前置當作不存在。只認兩端都存在的相依。

| #   | 情況                                 | 開始日                                                         | `explainSchedule` |
| --- | ------------------------------------ | -------------------------------------------------------------- | ----------------- |
| 1   | 已開始                               | 記錄的實際開始日。不受前置與今天影響                           | `actual`          |
| 2   | 未開始、沒有前置（根任務）           | 使用者設的開始日；不是工作天就順延到下一個工作天               | `root`            |
| 3   | 未開始、有前置                       | 每個前置「推算結束日的下一個工作天」裡最晚的那天（完成到開始） | `pred`            |
| 4   | 未開始，而且 2、3 算出的日子早於今天 | 今天；今天不是工作天就順延到下一個工作天                       | `today`           |

- 前置用的是推算結束日。前置晚完成、逾期未完成，還沒開始的後續任務都會往後推。
- 已開始的任務不會被前置或今天推動。
- 移植時的邊界：已開始卻沒有開始日的舊資料，照未開始推算；根任務沒有開始日時從今天算。

## 結束日

| 情況                                               | 結束日                                                         | `explainSchedule` |
| -------------------------------------------------- | -------------------------------------------------------------- | ----------------- |
| 完成                                               | 完成日。完成日早於開始日時用開始日（編輯入口會擋，這裡是防呆） | `done`            |
| 其他                                               | 從開始日起算第「工期」個工作天                                 | `duration`        |
| 進行中或暫停，而且上一列算出的日子早於今天（逾期） | 今天；今天不是工作天就順延到下一個工作天                       | `overdue`         |

- 逾期未完成的任務，結束日每天往後推，還沒開始的後續任務跟著推。
- 移植時的邊界：狀態是完成、卻沒有完成日的舊資料，照工期推算，不套逾期。

## 例：10/08 起 3 個工作天

用 2026 年的官方日曆，工期 3、開始日 2026-10-08：

| 日期       | 星期 | 工作天       | 第幾天 |
| ---------- | ---- | ------------ | ------ |
| 2026-10-08 | 四   | 是           | 1      |
| 2026-10-09 | 五   | 否（補假）   | —      |
| 2026-10-10 | 六   | 否（國慶日） | —      |
| 2026-10-11 | 日   | 否（週日）   | —      |
| 2026-10-12 | 一   | 是           | 2      |
| 2026-10-13 | 二   | 是           | 3      |

- 結束日是 2026-10-13。
- 它的後續任務最早 2026-10-14 開始。

## 狀態改變時寫入的值

改狀態時，存的值這樣改：

| 改變                  | 開始日                                                   | 完成日                   |
| --------------------- | -------------------------------------------------------- | ------------------------ |
| 未開始 → 進行中／暫停 | 記成今天                                                 | —                        |
| 未開始 → 完成         | 記成今天                                                 | 記成今天（已有值就不動） |
| 進行中／暫停 → 完成   | 不變                                                     | 記成今天（已有值就不動） |
| 完成 → 進行中／暫停   | 不變                                                     | 清空                     |
| 已開始 → 未開始       | 不變。根任務把它當成設定的開始日；有前置的改回由規則推算 | 清空                     |

- 同一次編輯同時帶狀態與開始日時，用編輯帶的開始日，不記成今天。
- 計畫開始日（`baselineStart`）不跟著狀態變：根任務開工後開始日改記實際開工日，計畫開始日留著，所以晚開工算延遲。
- 完成日就是實際結束日。改完成日跟改工期一樣，會推動還沒開始的後續任務。

## 不會生效的輸入不寫進資料

- 有前置、未開始的任務，開始日由前置決定。對它改開始日，這個值直接丟掉，不寫進資料。
- 已完成的任務，結束日就是完成日：改工期直接丟掉；完成日也不能清掉（清掉會變成「完成卻沒有完成日」）。完成日是空的舊資料，任何一次編輯都補上今天。要改回未完成，先改狀態。
- 原因：存了卻不會生效的值，會變成一筆永遠送不出去的本地變更。

寫進資料前一併夾值：

| 欄位                 | 夾在                                                       |
| -------------------- | ---------------------------------------------------------- |
| 工期                 | 1–3650；不是數字就丟掉                                     |
| 進行中／暫停的開始日 | 不晚於今天                                                 |
| 完成的開始日         | 不晚於完成日                                               |
| 完成日               | 不早於開始日。改的是完成日就夾完成日；改其他欄位就夾開始日 |

## 編輯限制

不能編輯時，畫面寫出原因（看得見的一行字或 title，觸控也看得到）。原因代碼：

| 代碼          | 什麼時候       | 不能做什麼                                                                                            |
| ------------- | -------------- | ----------------------------------------------------------------------------------------------------- |
| `predecessor` | 有前置、未開始 | 改開始日：甘特條不能整條拖、沒有左把手、日期選擇器的開始日停用                                        |
| `done`        | 已完成         | 改工期與結束日：沒有右把手、±1 停用、工期欄唯讀。也不能整條拖、沒有左把手；開始日只能從日期選擇器更正 |

各入口送出什麼（送的都是存的值，畫面再由排程推算）：

| 入口                   | 送出                                                                     | 限制                                                                                            |
| ---------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| 甘特條整條拖           | 開始日（工期不變）                                                       | 受 `predecessor`、`done` 擋。進行中／暫停的開始日不晚於今天                                     |
| 甘特左把手             | 開始日＋工期（結束日留在原地）                                           | 受 `predecessor`、`done` 擋。不越過結束日；未開始的不早於今天，進行中／暫停的不晚於今天         |
| 甘特右把手             | 工期＝開始日到拖到那天的工作天數                                         | 受 `done` 擋。不越過開始日；逾期時拖到今天以前不送                                              |
| 卡片 ▲▼、列選單 +1／−1 | 有效工期 ±1（見〈有效工期〉）                                            | 受 `done` 擋。逾期時 −1 停用（結束日最早是今天）。上下限 1、3650                                |
| 日期選擇器：選開始日   | 開始日（工期不變，等於整段平移）                                         | 受 `predecessor` 擋，選擇器一開就對準結束日。進行中／暫停：今天以後停用。已完成：完成日以後停用 |
| 日期選擇器：選結束日   | 工期＝開始日到那天的工作天數。點在開始日之前、而且開始日能改時，起訖對調 | 受 `done` 擋。開始日不能改時，開始日以前停用。逾期時今天以前停用                                |
| 日期選擇器：工期欄     | 工期                                                                     | 受 `done` 擋（唯讀）                                                                            |
| 完成日選擇器           | 完成日                                                                   | 開始日以前停用                                                                                  |
| 改狀態                 | 狀態，連帶的值見〈狀態改變時寫入的值〉                                   | —                                                                                               |

## 相依變動時

- 新增相依：後續任務若原本是根任務，開始日改由規則推算。相依建立成功後，才把被推動的任務寫回；建立失敗就不寫回，畫面照原本的相依排回去。
- 刪除相依、刪任務、刪分類：因此失去所有前置、而且還沒開始的任務，變成根任務。把它刪除當下的推算開始日記成「設定的開始日」。
- 這個開始日要在改相依之前記下來。不記的話，開始日會退回很久以前存的值（或今天），刪一條相依整段排程就跳一次。

## 存與算的分工

存的值（`Task` 的欄位）分三種：

| 種類   | 欄位                                                                                                                    |
| ------ | ----------------------------------------------------------------------------------------------------------------------- |
| 輸入值 | `duration`、`status`、`done`；已開始任務的 `start`（實際開始日）；未開始根任務的 `start`（設定的開始日）                |
| 快照   | 未開始、有前置任務的 `start`；所有任務的 `end`。都是上一次推算並寫回的值                                                |
| 計畫   | 根任務的 `baselineStart` 是輸入值（計畫開始日）；其餘的 `baselineStart`／`baselineEnd` 是計畫的快照（見〈計畫與延遲〉） |

- 畫面一律顯示推算起訖：用今天與工作日曆把存的值重排一次。跨日、日曆晚到都會自動重排。
- 載入不寫回。跨日之後畫面可能跟存的值不同，等下一次有人編輯時才一起寫回。
- 寫回（使用者編輯時）：
  - 送「推算結果跟最後已知 server 狀態不同」的任務，整批一次（`updateTasks`）。包括被這次編輯推動的下游，以及跨日之後被推動、還沒寫回的任務。
  - 別處還沒送出的本地編輯（拖曳中、改名 debounce 中）不跟著送，由它自己送。它的下游（沿相依往下走得到的任務）也先不送：下游的推算位置來自那筆還沒送出的編輯，例如拖曳的中途位置。
  - 建立中的任務等建立成功後再送。
  - 工作日曆不是 ready（載入失敗、還沒載完）時只送這次改的任務：只扣週末的推算是錯的，漂移與被推動的下游等日曆恢復後的下一次寫回再送。它們隨時能重算，不送也不會丟。
  - 只改不牽動排程的欄位（名稱、優先度、負責人），而且要送的只有它自己時，送單筆 patch。
- 後端不跑排程：只存前端送來的推算結果，response 回最終狀態。
- 唯讀的人（不是這個專案的 PM）只重算畫面，不寫回。
- 專案摘要（總覽的起訖、延遲數、計畫應完成數）也用推算結果，跟 Dashboard 看到的一致。

## 計畫與延遲

計畫只用 PM 輸入的東西排：根任務的計畫開始日、每個任務的工期、相依。PM 改了這些，計畫就跟著改，不用另外確認；現實造成的落後才算延遲。

| #   | 計畫的開始日                                                                    | 計畫的結束日                       |
| --- | ------------------------------------------------------------------------------- | ---------------------------------- |
| 1   | 根任務：計畫開始日（`baselineStart`；舊資料沒有時用 `start`），不是工作天就順延 | 從計畫開始日起算第「工期」個工作天 |
| 2   | 有前置：每個前置「計畫結束日的下一個工作天」裡最晚的那天（完成到開始）          | 同上                               |

- **不看今天與實際進度**：實際開工日、完成日、逾期、「還沒開始的不早於今天」都不影響計畫。程式是 `planTasks`；`scheduleWithPlan` 把它填進推算結果的基準欄位，畫面與總覽摘要都用它。
- **PM 改了就是新計畫**：
  - 改未開始根任務的開始日（日期選擇器、拖曳）：同時寫進 `baselineStart`（`applyTaskEdit`）。
  - 改工期、加減相依：計畫照上表重排，被影響的下游一起改。
  - 刪相依讓任務變成根任務：把它此刻的計畫開始日釘進 `baselineStart`（`pinNewRoots`），計畫不跳。
  - 已開始任務的開始日是實際值；改它（更正實際開工日）不動計畫。
- **現實造成的才算延遲**：時間到了沒做完（逾期，推算結束日推到今天）、該開始沒開始（推到今天）、前置晚完成把後續任務往後推。例：A 計畫 5 天、B 接在 A 後面。PM 把 A 改成 8 天，A、B 的計畫一起往後 3 天，不算延遲；A 做到第 6 天還沒完成，A 和被推動的 B 都算延遲。PM 把逾期的 A 工期拉長，計畫跟著延長，延遲就消失（PM 說了算）。
- **提早開工**：計畫不看實際開工日。任務在計畫開始日之前就開工（例：前置還沒完成就先做），照工期早該完成而還沒完成時，只要推算結束日沒晚於計畫結束日就不算延遲。範例的 t3 就是這樣（見〈檢查點〉）。
- **寫回**：計畫起訖跟推算起訖一起寫回（`updateTasks`）。根任務的 `baselineStart` 是輸入值；其他是快照，跟 `end` 一樣隨時能重算。
- **新增任務**：計畫開始日＝設定的開始日，計畫起訖一建立就算好，不會一出生就延遲。
- **沒有計畫的任務**（基準欄位是空的舊資料）：根任務用 `start` 當計畫開始日，寫回後就有計畫。
- 基準起訖一起有值或一起是空（資料表有 CHECK）。

### 已延遲與計畫進度

- 已延遲：未完成，而且推算結束日晚於計畫結束日。沒有計畫不算。
- 晚幾個工作天：計畫結束日的隔天到推算結束日之間的工作天數。例：計畫結束 09-16、推算結束 09-18（都是工作天）→ 晚 2 個工作天。
- 計畫應完成：計畫結束日**早於**今天。今天到期的任務今天還不算，隔天才算。
- 用到這兩個定義的地方：Dashboard 摘要卡的理論進度、延遲篩選、甘特／看板／屬性面板的延遲標示、總覽的 `delayedTasks` 與 `taskPlanned`。

## 有效工期

畫面上的工期、±1、右把手、工期排序都用它（看的是推算後的任務）：

| 狀態         | 有效工期                                      |
| ------------ | --------------------------------------------- |
| 未開始       | 輸入的工期                                    |
| 進行中／暫停 | max(輸入的工期, 開始日到推算結束日的工作天數) |
| 完成         | 開始日到完成日的工作天數，至少 1              |

- 逾期時，有效工期大於輸入的工期。例：範例的 t3 在 2026-09-18：09-08 開工、輸入工期 7，結束日推到 09-18，有效工期 9。
- ±1 以有效工期為準：t3 按 +1 送出工期 10，結束日變成 09-21。

## 檢查點（測試向量）

輸入是範例資料：

- `frontend/src/mocks/sampleProject.ts`：30 個任務、27 條相依；基準欄位存的就是計畫。
- `frontend/src/mocks/sampleCalendar.ts`：2026、2027 的官方日曆，`coveredYears = [2026, 2027]`。

在下列「今天」推算：

| 今天             | 延遲任務 | 晚幾個工作天  | 計畫應完成 | 專案結束日 |
| ---------------- | -------- | ------------- | ---------- | ---------- |
| 2026-09-18（五） | t13      | t13：4        | 5          | 2026-11-18 |
| 2026-09-19（六） | t8、t13  | t8：1、t13：5 | 6          | 2026-11-18 |
| 2026-09-22（二） | t8、t13  | t8：2、t13：6 | 6          | 2026-11-18 |

- 三天的專案開始日都是 2026-08-24；實際完成都是 4 筆（t1、t2、t7、t28）。
- 存的起訖就是 2026-09-18 的推算結果。那天推算，沒有任何任務改變（不動點）。
- 2026-09-19 是週六，「今天」順延到 09-21（一）。t3、t8、t13 的結束日推到 09-21，其他任務不變：這三筆的後續任務（t4、t9、t14）都已開始，不會被推。
- 2026-09-22：t3、t8、t13 的結束日推到 09-22，其他任務不變。
- t8 照工期剛好 09-18 結束，所以 09-18 還沒逾期，09-19 起才延遲。
- t3 也逾期（09-08 開工、工期 7，照工期 09-16 該結束），但不算延遲：它的前置鏈（t28 → t1 → t2）有幾筆在前置完成前就開工，t3 的計畫是 09-17～09-29，推算結束日還早於計畫結束日（見〈計畫與延遲〉的提早開工）。
- 範例本身的一致性由 `frontend/src/mocks/__tests__/consistency.spec.ts` 守。

## 已知限制

- **跨日不自動寫回**：沒有人編輯時，存的起訖會落後畫面，直到下一次編輯。總覽摘要用同一套排程重算，數字跟畫面一致；直接讀資料庫看到的是上次寫回的快照。
- **日曆載入失敗期間的寫回**：只送這次改的任務，但它本身仍是只扣週末的推算（畫面有「假日資料載入失敗」的提示）；漂移與被推動的下游不寫回。日曆恢復後，下一次編輯會把它們一起重排寫回。這次改的任務的計畫同樣只扣週末，日曆恢復後重算。
- **結束日剛好是今天的進行中任務**（例：2026-09-18 的 t8）：卡片 ▼、列選單 −1、右把手往前拉、日期選擇器選今天以前，都會照樣縮短存的工期，任務因此變成逾期。結束日最早是今天，所以條不會動，顯示的有效工期也不變。這是刻意的（2026-10-03 定案）：PM 的調整就是最高指導原則，縮短工期就該變逾期。只有已經逾期的任務才停用這些操作，因為再縮短也不會改變任何東西。
- **未公布的年份只扣週末**：官方日曆還沒匯入的年份不扣假日，畫面有提示。
- **不支援**：延後天數（lag）、其他相依種類（開始到開始等）、資源排程、保留最早的原計畫（PM 改了就是新計畫，舊的不留）。
